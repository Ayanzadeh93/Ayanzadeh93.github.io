## Contact Form

The contact block (details + form) is generated by `render_contact()` in
`scripts/build_site.py` into `index.html` and `contact.html`:

```html
<form action="https://formspree.io/f/xzdkodzv" method="POST" data-contact-form data-owner-email="…">
    <input type="hidden" name="_replyto" value="">
    <!-- name, email, subject, message fields -->
</form>
```

Validation and the fetch submit are `initContactForm()` in `js/site.js`, keyed on
`data-contact-form`. The newsletter form on `blog.html` uses the same handler.

## CSS Token Quick Reference (`css/site.css`)

| Token | Purpose |
|-------|---------|
| `--c-bg`, `--c-bg-soft`, `--c-bg-sunk`, `--c-surface` | Page, tinted section, sunk, and card surfaces |
| `--c-ink`, `--c-ink-2`, `--c-ink-3` | Text hierarchy (all ≥ 4.5:1 on every surface) |
| `--c-brand`, `--c-brand-strong`, `--c-brand-tint` | Links, primary buttons, accepted pills |
| `--c-accent`, `--c-accent-strong`, `--c-accent-tint` | Copper accent: rules, eyebrows, pending pills |
| `--c-line`, `--c-line-strong`, `--c-control` | Hairlines; `--c-control` is the 3:1 boundary for inputs and chips |
| `--f-display`, `--f-body`, `--f-mono` | Newsreader, Atkinson Hyperlegible, system mono |
| `--t-xs` … `--t-2xl` | Type scale (fluid at the top end) |
| `--s-1` … `--s-8`, `--s-sec` | Spacing; `--s-sec` is section padding |
| `--w-page`, `--w-read` | 1200px container, 44rem reading measure |

Dark values: `:root[data-theme='dark']` in the same file. The legacy tokens
(`--primary-color`, `--text-dark`, …) in `css/style.css` belong to Projects.

## Publication Record (`data/publications.json`)

```json
{
  "id": "pursuhint",
  "title": "PURSUhInT: In Search of Informative Hint Points Based on Layer Clustering for Knowledge Distillation",
  "title_lead": "PURSUhInT:",
  "authors": ["Reyhan Kevser Keser", "Aydin Ayanzadeh", "…"],
  "type": "article",
  "year": 2023,
  "venue": "Expert Systems with Applications",
  "venue_short": "Expert Systems with Applications",
  "venue_line": "Expert Systems with Applications, vol. 213, 119040, 2023",
  "status": "published",
  "volume": "213",
  "pages": "119040",
  "doi": "10.1016/j.eswa.2022.119040",
  "arxiv": "2103.00053",
  "topic": "efficient",
  "selected": true,
  "summary": "One sentence shown in lists and searched.",
  "links": { "code": "https://codeocean.com/capsule/4245746/tree/v1" },
  "bibtex": "@article{keser2023pursuhint,\n  …\n}",
  "page": {
    "description": "Meta description for the paper page.",
    "figures": [{ "svg": "assets/figures/<id>-fig1.svg", "caption": "…" }],
    "abstract_heading": "Abstract",
    "abstract": ["Paragraph one.", "Paragraph two."],
    "notes": ["Optional caveat shown under the abstract."],
    "method_heading": "Method",
    "method_layout": "steps",
    "method": [{ "title": "Step name", "text": "What it does." }],
    "resources": [{ "label": "DOI", "text": "10.1016/…", "url": "https://doi.org/10.1016/…" }]
  }
}
```

Field notes:

| Field | Notes |
|-------|-------|
| `type` | `article` · `inproceedings` · `incollection` · `preprint`. Drives the facet chips, the JSON-LD type and the Google Scholar tags. |
| `status` | `published` · `accepted` · `under-review` · `preprint`. Only *accepted* and *under submission* show a pill. |
| `venue` | Container title only; `venue_line` is the prose line and should contain `venue` verbatim so it can be set as `<cite>`. |
| `pages` | A range (`2855-2868`) or a bare article number (`119040`). |
| `doi` / `arxiv` | Rendered as Publisher / arXiv buttons. An arXiv DOI (`10.48550/arXiv.…`) is not shown as a publisher link. |
| `links` | `pdf`, `publisher`, `code`, `slides`, `book`. Omit what does not exist. |
| `figures` | `svg` (a file under `assets/figures/`, inlined) or `src` + `alt` (remote image; degrades to a note if it fails to load). |
| `external_page` | For a paper whose page lives elsewhere; replaces `page`. |
| `bibtex` | Curated entry, used verbatim in the page, the cite dialog and `assets/publications.bib`. Its key must be unique. |

Display order: newest year first; within a year, the order of the file.

## Component Map

| Element | File | What it does |
|---------|------|--------------|
| `<pub-library>` | `js/components/pub-library.js` | Enhances the generated library: ranked search, type and research-thread facets, `/` focus shortcut, shareable `?q=&type=&topic=` URL. |
| `<cite-dialog>` | `js/components/cite-dialog.js` | One per page; native `<dialog>` exporting BibTeX / APA 7 / MLA 9 / IEEE plus a `.bib` download. Opened by any `<button data-cite="<id>" hidden>`. |

Supporting modules, all pure and side-effect free:

| Module | Exports |
|--------|---------|
| `js/lib/dom.js` | `el`, `appendChildren`, `clear`, `escapeHtml`, `debounce`, `prefersReducedMotion`, `withViewTransition`, `copyText` |
| `js/lib/citations.js` | `parseAuthors`, `splitName`, `bibKey`, `canonicalUrl`, `formatBibTeX/APA/MLA/IEEE`, `formatCitation`, `CITATION_FORMATS` |
| `js/lib/search.js` | `normalize`, `tokenize`, `scoreRecord`, `filterRecords`, `matchRanges`, `buildHaystack` |
| `js/lib/pub-data.js` | `publicationRecords` — reads the generated `<script type="application/json" id="pub-data">` island |

Search semantics: tokens are AND-ed (every token must match somewhere), matching
is diacritic-folded (`Toreyin` finds `Töreyin`), and field weights are
title 10 / authors 6 / venue 4 / tags 3 / year 2.

## Adding a Custom Element

1. Write the module in `js/components/`, keeping any reusable logic in `js/lib/`.
2. Guard registration: `if (!customElements.get('x-y')) customElements.define(…)`.
3. Import it from `js/components/index.js` — pages load only that entry.
4. Style it in `css/site.css` using its tokens.
5. Enhance markup that is already in the page. If the element renders content
   that is not in the HTML, the no-JS and crawler view loses it.
6. Ship JS-only controls as `hidden` in the markup and unhide them on upgrade.

## CLI Catalog Entry Template

Records live in the standalone [`claude-code-encyclopedia`](https://github.com/Ayanzadeh93/claude-code-encyclopedia)
repo (`data/catalog.json`). The live app is
https://www.ayanzadeh.com/claude-code-encyclopedia/. Adding a `gh` command is a
data edit in that repo. Older `apps/claude-code-catalog.html` URLs on this site
redirect there and keep query and hash.

```json
{
  "id": "ghpr-gh-pr-merge",
  "section": "ghpr",
  "name": "gh pr merge",
  "type": "Pull request",
  "description": "One sentence, present tense, saying what the command does.",
  "aliases": [],
  "examples": [
    { "command": "gh pr merge 42 --squash --delete-branch", "label": "squash" }
  ],
  "introducedVersion": null,
  "tags": ["pull request", "merge", "squash"],
  "note": "The caveat a reader would otherwise learn the hard way, or null."
}
```

| Field | Rule |
|-------|------|
| `id` | `<section>-<slugified name>`, unique across the file. Also the deep-link anchor, so keep it stable. |
| `section` | Must exist in `sections`; that section's `family` must exist in `families`. |
| `name` | Rendered in monospace as the card heading. Unique within its section. |
| `description` | One sentence. The card summary, and a mid-weight search field. |
| `examples` | Each needs `command` and `label`. The label captions the code block — name the surface (`shell`, `json`, `settings.json`, `enterprise`). |
| `tags` | At least one. Searchable, and the first six render as chips. |
| `note` | Use it for the caveat, not for restating the description. `null` when there isn't one. |

Search in the live encyclopedia is name-first and token AND-ed.

Two rendering modes, chosen by whether a query is active:

- **No query** — entries are grouped under section headings in the catalog's
  authored order, so the page reads as a document.
- **With a query** — a flat list in relevance order. Grouping here would re-sort
  the results and bury the best match under whichever section sorts first.

### Adding a family

1. Append to `families` with `id`, `label`, `blurb` and `source`.
2. Add its sections to `sections`, each carrying that `family` id.
3. Add entries. The validator rejects an empty family or an empty section, so a
   new family must ship with content.
4. Run `python tests/validate_content.py`.
