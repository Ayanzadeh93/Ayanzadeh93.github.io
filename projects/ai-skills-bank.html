Overview

Most prompt libraries are a pile of paragraphs. They are useful once, then the wording drifts, the file gets renamed and nobody can tell which behavior a teammate meant. The AI Skills Bank gives every reusable behavior a short, stable identity: CS-009 is always Code Review Partner, and GS-016 is always the step-by-step enforcer.

The library ships 500 skills, 50 in each of ten categories, as plain Markdown. Every skill is one ID, one name and one actionable line. Copy the line into CLAUDE.md, AGENTS.md, GEMINI.md or any agent instruction field, or reference the ID in a spec, a review or a routing rule.

The same data powers a searchable public catalog at ayanzadeh.com/skills, a machine-readable skills.json index, and configuration packs for Claude Code, Codex CLI, Gemini CLI, Kimi CLI, Aider and Cline. MIT licensed, self-hosted, no account.

Using a Skill

1. Paste the one-line prompt

A skill is deliberately short enough to sit in a system prompt or a context file without swallowing the task.

Example

You are CS-009 — Code Review Partner. Performs a human-style code review with comments and priority labels.

2. Or list IDs in your project instructions

IDs are easier to route, diff and review than repeated prose. Keep the active set small and explicit.

CLAUDE.md / AGENTS.md

## Active skills
- GS-016 — "Think Step by Step" Enforcer
- CS-009 — Code Review Partner
- GS-020 — Risk & Edge-Case Spotter

3. Or query the JSON index

The public index keeps the catalog and any downstream tool in sync with the Markdown source.

skills.json

{
  "id": "RS-004",
  "name": "Full-Paper Summarizer",
  "description": "Summarizes long papers into structured briefs (context, method, results).",
  "category": "Research & Reading",
  "file": "skills/skills-research-reading.md"
}

Why IDs matter: a renamed prompt is a new behavior to everyone downstream. A stable ID keeps reviews, routing rules, eval cases and documentation pointing at the same skill even when the wording is improved.

How It Is Built

1. Markdown Is the Source of Truth

Ten files, one per category, hold the 500 skills. Adding a skill is a one-line edit in the file that owns its prefix; nothing else needs to be rewritten by hand.

2. A Build Script Derives the Index

A dependency-free Node script parses the Markdown and emits skills.json with a schema version, category metadata, counts and every skill record. The catalog on this site is generated from the same JSON, so the page and the API cannot disagree silently.

3. CI Checks the Invariants

The validation workflow checks ID format, uniqueness, category membership, the 50-per-category count and the generated index. It caught a real bug: 1,028 IDs had been written with a non-breaking hyphen that looked identical to a normal one but broke copy, search and grep. Every ID is ASCII now, and the check keeps it that way.

4. The Catalog Is Static

The public catalog is pre-rendered HTML with client-side search and copy buttons. There is no framework, no API call and no build step at request time; GitHub Pages serves the whole thing.
